スクロールを数字に変える

「まる珈琲の値段」で使ったアニメーションの作り方を、全部ひらいて説明します。アニメーションにライブラリは一つも使っていません。すべてブラウザの標準機能です。各節にスライダーで動かせる実験台を置いたので、数字を動かして結果を確かめながら読んでください。

00全体の設計

最初にここを掴むと、あとの話が全部つながります。素朴に作ると、こういう JavaScript を書きたくなります。

// よくある書き方
window.addEventListener('scroll', () => {
  coin.style.transform = 'translateY(' + y + 'px)';
  coin.style.opacity   = op;
  sack.style.transform = 'translateX(' + x + 'px)';
  // ...動かしたい要素の数だけ延々と続く
});

これだと、要素が増えるたびに JavaScript が太っていきます。本編にはコイン 10 枚、タイル 6 枚、袋、金庫、棒グラフ…と数十個あるので、この書き方では破綻します。

そこで役割を分けました。JavaScript は「このセクションは今、何%まで進んだか」という数字を 2 つ書くだけ。それを受けて、コインが何枚出るか・袋がどこまで動くかは、CSS 側が各自で決めます。

設計図

この受け渡しに使うのが CSS カスタムプロパティ（CSS 変数） です。おかげで本編の JavaScript は全体で 60 行ほどに収まっています。

01スクロールを数字にする

まず「どのくらいスクロールしたか」を測ります。getBoundingClientRect() を使うと、要素が今、画面のどのへんにいるかが取れます。

var r = el.getBoundingClientRect();
// r.top    → 要素の上端が、画面の上端から何px下にあるか
// r.height → 要素自体の高さ
// vh       → 画面の高さ (window.innerHeight)

r.top が画面基準なのがポイントです。スクロールすると勝手に減っていきます。要素が画面のずっと下にあれば +2000 のような大きな正の数、通り過ぎて上に消えれば負の数になります。これを 0〜1 に変換します。

var p = (vh - r.top) / (vh + r.height);
p = p < 0 ? 0 : (p > 1 ? 1 : p);   // 0〜1 からはみ出さないよう固定

var c = ((r.top + r.height / 2) - vh / 2) / vh;

分母が vh + r.height なのは、「画面の下から入ってきて、上から出ていくまで」の総移動距離がそれだからです。--c のほうは画面中心からのズレで、要素が画面より下なら +、上なら −、ちょうど中央で 0 になります。傾きの計算に使います。

枠内をスクロールすると数字が動きます

破線が枠の中央です。要素の中心がここに重なると --c が 0 になります。

実際に動かすと分かりますが、--p は下から入ってきた瞬間が 0、通り抜けた瞬間が 1。--c は中央で符号が入れ替わります。この 2 つの数字だけで、あとの動きは全部作れます。

02CSS変数のバケツリレー

計算した値は、要素に直接書き込みます。

el.style.setProperty('--p', p.toFixed(4));
el.style.setProperty('--c', c.toFixed(4));

setProperty は、style 属性に --p: 0.6231 と書くのと同じことです。ここで効いてくるのが、CSS 変数は子孫要素に自動で継承されるという性質。セクションに書けば、その中の全員が読めます。JavaScript から個々の要素を探しに行く必要がありません。

html.motion .sack{
  transform: translateX(calc((1 - var(--p)) * 130px));
}

--p が 0 のとき (1-0) × 130px で右に 130px ずれた位置。1 になると 0、つまり定位置。借金の袋が右から滑り込んでくるのは、この 1 行だけです。2 軸同時に動かすのも同じ要領。

html.motion .cashbox{
  transform: translate(calc((1 - var(--p)) * 44px), calc(var(--p) * -32px));
}

横は近づき、縦は --p が増えるほどマイナス方向＝上へ浮き上がる。式を差し替えるだけで動きの性格が変わるので、調整がとても速くなります。

CSS 変数は「値の入れ物」であって「計算結果」ではありません。--p が変わると、それを使っている全ての calc() が自動的に再計算されます。JavaScript から再計算を指示する必要はありません。

03イベントを間引く

スクロールイベントは 1 回のスワイプで何十回も飛んできます。毎回まじめに処理すると重くなるので、requestAnimationFrame で画面の描画タイミングに合わせて 1 回だけ実行します。

var pending = false;

function onScroll(){
  if (!pending) {              // すでに予約済みなら何もしない
    pending = true;
    requestAnimationFrame(update);
  }
}
function update(){
  pending = false;             // 実行したら予約を解除
  /* ... 計算 ... */
}
window.addEventListener('scroll', onScroll, { passive: true });

pending フラグが肝です。イベントが 30 回飛んできても、次の描画までに実行されるのは 1 回だけ。この形は rAF スロットリングと呼ばれる定番パターンで、resize や mousemove にもそのまま使えます。

{ passive: true } は「このリスナーは preventDefault() を呼びません」という宣言です。ブラウザはスクロールを止める必要がないと分かるので、リスナーの完了を待たずに画面を動かせます。スマホでの指の追従が目に見えて変わります。

さらに、画面外のセクションは計算ごと飛ばしています。

if (r.bottom < -vh || r.top > vh * 2) continue;

04動かしていいのは 2 つだけ

これが今回いちばん大事な原則です。ブラウザは画面を描くのに 3 段階を踏みます。

段階やることコスト
① Layoutどこに何を置くか計算する重い
② Paintピクセルに色を塗るそこそこ重い
③ Compositeできた層を重ねる（GPU が担当）軽い

width height top left margin などを変えると①から全部やり直しになります。60 分の 1 秒ごとにこれをやるとカクつきます。いっぽう transform と opacity は ③ だけで済みます。要素の中身はすでに画像として GPU に載っているので、それを動かしたり透かしたりするだけです。

/* カクつく — 毎フレーム Layout からやり直し */
.sack{ left: calc((1 - var(--p)) * 130px); }

/* 滑らか — Composite だけで済む */
.sack{ transform: translateX(calc((1 - var(--p)) * 130px)); }

正直な注記。最近の PC は速いので、要素数が少ないうちは両者に差が出ません。スライダーを 600 以上に上げ、left 側の fps が落ちるかを見てください。差が開かない環境もありますが、そのときも仕組み上の負荷差は存在します。古いスマホや、要素が重いページで顕在化します。ブラウザの DevTools の Performance タブで記録すると、left 側にだけ紫色の Layout が並ぶのが見えます。

アニメーションは transform と opacity だけ — まずこれを体に入れておくと、たいていの「なんか重い」は避けられます。

05clampで時間差を作る

コインが下から 1 枚ずつ積み上がる部分です。ここは JavaScript を一切使っていません。まず HTML 側で、各コインに通し番号を持たせます。

<g class="coin" style="--i:0"><use href="#coinshape"/></g>
<g class="coin" style="--i:1"><use href="#coinshape"/></g>
<g class="coin" style="--i:2"><use href="#coinshape"/></g>
<!-- ... --i:9 まで -->

CSS はこれだけです。

html.motion .coin{
  --k:  calc((var(--p) - .2) * 16);
  --on: clamp(0, calc(var(--k) - var(--i)), 1);
  opacity: var(--on);
  transform: translateY(calc((1 - var(--on)) * -46px));
}

--k は「今、何枚目まで出していいか」を表す進行カウンタです。--p から 0.2 を引いているので、スクロールが 20% 進むまでは動きません（入ってすぐ始まると気付かれないため）。× 16 は速度で、上げると一気に積み上がります。

--on が各コイン自身の「出現度」。--k − --i は「自分の番が来てから、どれだけ経ったか」です。clamp(0, 値, 1) は「0 未満なら 0、1 超なら 1、間ならそのまま」という関数。自分の番号と全体の進行度を比べるだけの式が、10 枚の時間差アニメーションになります。

実験 03 — clamp スタッガー--p を手で動かせます

16
右の表は各コインの --on（出現度）です。0 と 1 のあいだにいる 1 枚だけが、いま落ちてくる途中のコインです。

エスプレッソマシンの「60 万円が 6 年に分かれる」タイルも、同じ仕組みで番号と閾値を変えただけ。棒グラフも scaleX を進行度に紐付けています。

html.motion .bar path{
  transform: scaleX(clamp(.06, calc((var(--p) - .16) * 2.8), 1));
  transform-box: fill-box;
  transform-origin: left center;   /* 左端を固定して右へ伸ばす */
}

transform-origin を指定しないと中心から両側に伸びてしまいます。SVG では transform-box: fill-box を添えて「図形自身の枠を基準にする」と宣言しておくのが確実です。

06線を描くアニメーション

イラストの輪郭が手で描かれるように現れる部分です。原理は破線です。

stroke-dasharray は破線の「線の長さ」と「隙間の長さ」を指定します。ここで線の長さをパス全体の長さと同じにすると、パスが 1 本の線でぴったり埋まります。そこに stroke-dashoffset（破線のスタート位置をずらす量）を足すと、線が端から消えていく。L → 0 に変化させれば、描かれていくように見えます。

パスの長さ L = —
dasharray を小さくすると破線に、L と同じにすると一本の線になります。その状態で dashoffset を上げると、端から消えていきます。

パスの長さはブラウザに聞けます。getTotalLength() は、どんなに曲がりくねったパスでも実際の長さを px で返します。<circle> や <ellipse> でも使えます。

var draws = document.querySelectorAll('.draw');
for (var d = 0; d < draws.length; d++) {
  var len = Math.ceil(draws[d].getTotalLength()) + 4;
  draws[d].style.setProperty('--L', len);
}
.draw{ stroke-dasharray: var(--L, 1000); stroke-dashoffset: 0; }

html.motion .draw{
  stroke-dashoffset: var(--L, 1000);              /* 初期状態：消えている */
  transition: stroke-dashoffset 1.25s cubic-bezier(.3,.75,.3,1);
  transition-delay: calc(var(--i, 0) * 110ms);    /* 番号ぶん遅らせる */
}
html.motion .rv-in .draw{ stroke-dashoffset: 0; } /* 発火：描かれる */

--i で遅延をずらしているので、店の輪郭 → 屋根 → 日よけ → 窓 → 扉 と順に描かれます。1 本ずつ手で描いているように見えるのは、この 110ms のずれのおかげです。

湯気は逆に、わざと隙間だらけの破線を無限にずらし続けています。

.steam path{ stroke-dasharray: 5 9; animation: steamup 3.4s linear infinite; }
@keyframes steamup{ to{ stroke-dashoffset: -28; } }

07一度だけ発火させる

「描かれる」演出は、スクロールに張り付かせるのではなく一度だけ再生したいものです。これには IntersectionObserver を使います。

var io = new IntersectionObserver(function(entries){
  for (var i = 0; i < entries.length; i++) {
    if (entries[i].isIntersecting) {
      entries[i].target.classList.add('rv-in');  // クラスを付けて発火
      io.unobserve(entries[i].target);           // 二度と発火しないよう監視解除
    }
  }
}, { rootMargin: '0px 0px -10% 0px', threshold: 0.1 });

threshold を 1 にすると「全部見えるまで発火しない」、rootMargin を −40% にすると「かなり上まで来ないと発火しない」になります。
  • threshold: 0.1 … 要素の 10% が見えたら発火
  • rootMargin: '0px 0px -10% 0px' … 判定ラインを下端より 10% 内側へ。端ぎりぎりで発火して見逃す事故を防ぎます
  • unobserve … 発火したら監視をやめる。付けっぱなしだと往復スクロールで何度も再生されて鬱陶しくなります

スクロール連動（--p）と、一度だけ（IntersectionObserver）を使い分けるのが今回の構成です。位置に張り付いてほしい動きは前者、登場演出は後者。

08手描きと水彩の作り方

イラストが手描きに見えるのは、絵が上手いからではなくフィルタで線を歪めているからです。パス自体はきれいな直線や円で書いてあります。

<filter id="rough" x="-25%" y="-25%" width="150%" height="150%">
  <feTurbulence type="fractalNoise" baseFrequency="0.024" numOctaves="3" seed="11" result="n"/>
  <feDisplacementMap in="SourceGraphic" in2="n" scale="3"
                     xChannelSelector="R" yChannelSelector="G"/>
</filter>

feTurbulence は雲のようなランダムなノイズ画像を作ります。feDisplacementMap が本体で、「ノイズの色の濃さを見て、元の絵のピクセルをその分ずらす」フィルタです。xChannelSelector="R" は「横方向のずらし量はノイズの赤成分から取る」という意味。

scale ひとつで質感が決まります。3 なら手描きの線、30 なら水彩の滲み。ボタンで本編の 2 つの設定を切り替えられるので、見比べてみてください。seed は乱数の種で、変えると別のパターンになり、同じ値なら毎回同じ模様が出ます。

<filter id="wash" x="-35%" y="-35%" width="170%" height="170%">
  <feTurbulence ... baseFrequency="0.014" numOctaves="4" seed="5" result="n"/>
  <feDisplacementMap in="SourceGraphic" in2="n" scale="30" ... result="d"/>
  <feGaussianBlur in="d" stdDeviation="2.6"/>
</filter>

result="n" と in2="n" で前の工程の出力を次に渡しています。フィルタはパイプラインとして数珠つなぎにできるわけです。だから本編の背景の色ムラは、ただの <circle> にこのフィルタを掛けて、乗算で重ねただけです。

.wash{ mix-blend-mode: var(--wash-blend); opacity: var(--wash-op); filter: url(#wash); }

よくある落とし穴。x="-25%" width="150%" はフィルタの適用範囲です。デフォルトのままだと歪ませた部分が枠からはみ出して切れます。手描きフィルタを作って端が途切れるのは、ほぼこれが原因です。上のデモで scale を 40 まで上げても切れないのは、範囲を 190% に広げてあるからです。

09立体に見せる

3D は CSS だけで出せます。

.tilt > svg{
  transform: perspective(1300px)
             rotateX(calc(var(--c) * -4.5deg))
             rotateY(calc(var(--c) * 3.2deg))
             translate3d(0, calc(var(--c) * -26px), 0);
}

perspective() は「カメラと画面の距離」です。小さいほど広角レンズになり、パースが強くつきます。1300px はかなり控えめで、傾きが上品に出る範囲。

回転量に --c（画面中心からのズレ）を掛けているのがポイントです。

  • 画面下にあるとき（--c は正）→ 手前に傾いている
  • 画面中央（--c = 0）→ 回転ゼロ＝正面を向く
  • 通り過ぎたあと（--c は負）→ 逆に傾く

つまり読んでほしい位置に来たときだけ正面を向く。傾きが情報の邪魔をしません。

10壊れない設計

派手に動かすページほど、動かないときに壊れないことが大事です。3 つ用意しました。

1. JavaScript が動かなくても読める

アニメーションの初期状態（透明、線が消えている）は、すべて html.motion の下にだけ書いてあります。このクラスは JavaScript が付けます。

.rv{ transition: opacity .85s cubic-bezier(.22,.7,.28,1); }   /* 常に適用 */
html.motion .rv{ opacity: 0; transform: translateY(26px); }   /* JSが動いた時だけ */
html.motion .rv.rv-in{ opacity: 1; transform: none; }

JS が落ちれば .motion が付かない → 初期状態も適用されない → 全部そのまま見える。逆の書き方（デフォルトで opacity:0）にすると、JS が失敗した瞬間に真っ白なページになります。順序が命です。

2. 動きを求めていない人には動かさない

var mq = window.matchMedia('(prefers-reduced-motion: reduce)');
if (!mq.matches) document.documentElement.classList.add('motion');

OS の「視差効果を減らす」設定を読んでいます。前庭障害などで動く画面が体調に響く人がいるので、大きく動かすページでは必須の配慮です。CSS 側にも保険を入れてあります。

3. Observer が発火しなかった場合の保険

setTimeout(showAll, 5000);

5 秒経っても発火していない要素は、問答無用で全部表示します。稀な環境で「スクロールしても何も出てこない」状態に陥るのを防ぎます。
